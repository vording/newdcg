# 実装ルール整理（プロトタイプ v0.1）

仕様書 v0.3 をもとに、実装可能な形に整理したルール。
**【仮】** の付いた項目は仕様書で未確定のため仮置きしている（[open-questions.md](open-questions.md) 参照）。
数値はすべて `src/engine/config.js` で変更可能。

## 1. ゲーム開始
1. 各プレイヤーのデッキ（30枚・同名3枚まで）を検証する。
2. 先攻・後攻をランダムに決める。【仮】
3. 各デッキをシャッフルし、先攻は4枚、後攻は5枚引く。
4. マリガンはなし。【仮】
5. 先攻の第1ターンを開始する。

## 2. ターン進行
| フェイズ | 処理 | 備考 |
|---|---|---|
| 開始 | 最大マナ+1（上限10）→ 現在マナを最大まで回復 → 自分のクリーチャーの行動済み・召喚酔いを解除【仮】→ 開始時効果 | 自動 |
| ドロー | 1枚引く。先攻1ターン目も引く【仮】 | 自動 |
| メイン | カードを使う／攻撃宣言へ進む／ターン終了 | 手番プレイヤーが操作 |
| バトル | 攻撃宣言 → 防御側がブロック宣言 → 戦闘ダメージ | 攻撃しない場合はスキップ |
| エンド | 終了時効果 → 相手のターンへ | 自動 |

- バトルフェイズ後にメインフェイズへは戻らない（仕様書の順序どおり）。【要確認】
- 未使用マナは持ち越さない。

## 3. カードの使用
- メインフェイズに手番プレイヤーのみ使用可能。コスト分のマナを支払う。
- クリーチャー：場に5体いる場合は召喚不可。召喚したターンは攻撃不可（召喚酔い）。「速攻」持ちは攻撃可。
- スペル：対象が必要なものは合法な対象がいなければ使用不可。解決後は墓地へ。
- 召喚時効果は召喚直後に解決する。

## 4. 戦闘
1. 攻撃側は、攻撃可能なクリーチャーを**まとめて**宣言する。【仮：同時宣言方式】
   - 攻撃可能 = 行動済みでなく、召喚酔いでない（または速攻）。
   - 攻撃先は相手プレイヤーのみ（クリーチャーへの直接攻撃なし）。
   - 宣言したクリーチャーは行動済みになる。
2. 防御側はブロックを宣言する（しなくてもよい）。
   - 1体の攻撃につきブロッカー1体まで。1体のクリーチャーがブロックできるのは1体の攻撃のみ。
   - 行動済みのクリーチャーはブロックできない。【仮】
   - ブロックしたクリーチャーは行動済みにならない。【仮】
3. ダメージは全員同時に与える。
   - ブロックされなかった攻撃：攻撃力分を防御側プレイヤーへ。
   - ブロックされた攻撃：攻撃側と防御側が互いの攻撃力分を与え合う。超過分はプレイヤーに通らない。
4. 状態起因処理を行い、ターン終了へ。

## 5. ダメージと破壊
- クリーチャーのダメージは蓄積し、ターンをまたいでも回復しない。回復はカード効果のみ。
- `蓄積ダメージ ≥ HP` になったクリーチャーは破壊され墓地へ。

## 6. 状態起因処理・勝敗
- カード使用後・戦闘後・各フェイズ処理後に、破壊判定と勝敗判定を行う。
- ライフ0以下のプレイヤーは敗北。両者同時に0以下なら引き分け。【仮】
- デッキ切れでドローできない場合は何も起きない（`deckOutRule: 'skip'`）。【仮】
- 手札上限なし。【仮】
